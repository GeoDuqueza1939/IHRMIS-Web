# IHRMIS database — schema + seeds

## Source of truth

`.docsanddesign/DB-ERD.mwb` (MySQL Workbench model) is the **only** source of
truth for schema **and** seed rows:

- Schema (tables, columns, indexes, FKs, diagrams) lives in `document.mwb.xml`.
- Seed rows (entered via the Table Editor's **Inserts** tab) live in
  `@db/data.db` inside the same archive. `tools/mwb-edit.mjs` preserves that
  entry byte-for-byte on every write and reports row counts in
  `digest`/`wbcheck`; `apply` refuses to write output that lost seed rows.

Never hand-edit the SQL below — regenerate it.

Seed INSERTs are idempotent (`ON DUPLICATE KEY UPDATE`) so `schema.sql`
and `src/tools/seed-janus.mjs` converge regardless of run order.
`Role_Right` grants are intentionally NOT emitted here: role/right ids only
exist at deploy time and are resolved by the seeder.

## Files

- `schema.sql` — full schema (126 tables, FKs) + seed `INSERT`s, generated by
  `tools/mwb-ddl.mjs`. Self-contained: creates database `ihrmis`
  (utf8/utf8_general_ci), disables `FOREIGN_KEY_CHECKS` for the load.
- `README.md` — this file.

## Regenerate

```sh
node tools/mwb-ddl.mjs --mwb .docsanddesign/DB-ERD.mwb --out db/schema.sql
```

## Load (needs DB-admin credentials)

```sh
mysql -u root -p < db/schema.sql
```

Verify afterwards (expected values in parentheses):

```sql
SELECT COUNT(*) FROM INFORMATION_SCHEMA.TABLES WHERE TABLE_SCHEMA='ihrmis'; -- 126
SELECT COUNT(*) FROM INFORMATION_SCHEMA.REFERENTIAL_CONSTRAINTS WHERE CONSTRAINT_SCHEMA='ihrmis'; -- 195
SELECT * FROM ENUM_User_Status;      -- 4 rows
SELECT * FROM ENUM_User_Type;        -- 3 rows
SELECT * FROM ENUM_OAuth_Provider;   -- 4 rows
```

Then create the least-privilege app user and export the `IHRMIS_MYSQL_*`
variables the app (`src/modules/config.mjs` mysql block) reads.

## Tool homes (do not merge)

- `tools/` (repo root) — zero-dependency model tooling: `mwb-edit.mjs`,
  `mwb-ddl.mjs`, `mwb-inserts.py` (needs only python3 stdlib).
- `src/tools/` — runtime-adjacent scripts needing `src/node_modules`
  (e.g. `seed-janus.mjs`, which needs `mysql2`).

## Seed direction (agreed)

Model rows are canonical. `src/tools/seed-janus.mjs` is Duke's deploy-time
runner; its constants must stay identical to the model rows (ids, names —
descriptions included). Any drift found by diffing
`node src/tools/seed-janus.mjs --dry-run` against
`python3 tools/mwb-inserts.py` output is a bug; fix the model first.

## Known approximations

- `DATETIME_F` model columns render as plain `DATETIME` (fractional
  precision is not tracked distinctly enough to emit `(fsp)`); only affects
  `Team_Member.assigned/removed`, no JANUS impact.
- `ON UPDATE CURRENT_TIMESTAMP` is folded into the column's default
  expression (GRT has no column-level ON UPDATE key); the emitted
  `DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP` is valid SQL.
